# 岳麓山景点推荐系统毕业论文初稿

## 摘要

随着移动互联网与智慧旅游的持续发展，景区信息服务正由传统的静态展示逐步转向面向个体需求的智能推荐。岳麓山作为长沙重要的城市景区，兼具自然风光、历史人文与高校文化等多重旅游资源，游客在实际游览过程中常面临景点信息分散、路线选择困难、兴趣匹配不足等问题。针对上述问题，本文设计并实现了一套岳麓山景点推荐系统，为游客提供景点浏览、个性化推荐、收藏、评分、评论、经典线路匹配以及智能导游等服务，同时为管理员提供景点、路线、评论与用户管理能力，并通过数据看板辅助系统运营分析。

系统后端采用 Java 18、Spring Boot 2.7、MyBatis-Plus 与 MySQL 8 构建，前端采用 Vue 2、Element UI 与 Axios 实现前后端分离架构，用户认证使用 JWT 进行统一鉴权。推荐模块基于用户协同过滤思想，融合浏览、收藏与评分等行为信息构建用户兴趣画像，并结合时间衰减与多样性重排机制生成推荐结果；对于冷启动用户，则采用综合热度策略提供基础推荐。为增强推荐结果的可解释性，系统进一步设计了推荐理由生成机制，并在前台首页展示用户兴趣画像与推荐理由。此外，系统还设计了景点排行榜、后台数据看板以及 AI 导游模块，以提升系统的完整性和展示效果。

实验与运行结果表明，该系统能够较好地满足岳麓山景区个性化信息服务需求，具备较强的实用性与可展示性。本文的工作为高校毕业设计中旅游推荐系统的实现提供了一个可复现、易部署且具有一定创新性的参考方案。

**关键词**：智慧旅游；景点推荐；协同过滤；用户画像；数据看板

## 第1章 绪论

### 1.1 课题背景与研究意义

近年来，智慧旅游逐渐成为旅游信息化建设的重要方向。随着游客出行方式和信息获取渠道的变化，传统依赖宣传栏、人工讲解和静态网页的景区服务方式，已经难以满足游客对个性化、实时化与交互化服务的需求。尤其是在景区资源丰富、游览路径多样的场景下，游客往往需要在大量景点信息中进行筛选，既要考虑兴趣偏好，也要兼顾游玩时间、地理位置、路线顺序等因素，这使得景点选择和线路规划的决策成本明显上升。

岳麓山景区集自然风光、历史遗迹、校园文化和城市观景于一体，具有典型的综合性旅游资源特征。一方面，景区内景点数量较多，类型差异明显；另一方面，不同游客的兴趣差异较大，有的偏好历史文化，有的偏好自然风景，还有的更关注高空观景与打卡体验。因此，如果仅依赖静态景点介绍，很难帮助游客快速找到符合自身兴趣的游览对象。

基于上述背景，本文围绕岳麓山景区的实际应用场景，设计并实现了一个景点推荐系统。系统不仅提供基础的信息查询功能，还通过用户行为数据进行个性化推荐，使景点展示从“统一推荐”转变为“按需推荐”。同时，系统引入推荐理由、用户兴趣画像与排行榜等可视化内容，增强推荐结果的可解释性，便于用户理解系统为何推荐某些景点，也便于在毕业设计答辩中展示系统的完整性和技术价值。

从研究意义上看，本课题具有以下两方面价值。第一，在应用层面，它能够为游客提供更高效的景点筛选与路线参考，提升游览体验；第二，在实现层面，它将协同过滤、行为建模、前后端分离、数据可视化与后台管理等内容融合到一个完整系统中，具有较好的综合训练意义，符合计算机专业毕业设计的要求。

### 1.2 国内外研究现状

推荐系统最早广泛应用于电商、内容分发和媒体平台，核心目标是通过分析用户历史行为预测其未来偏好，并据此输出个性化结果。随着推荐技术的发展，协同过滤、内容推荐、混合推荐和深度学习推荐等方法不断涌现。其中，基于用户的协同过滤由于思路清晰、实现成本较低、可解释性较强，在中小型信息系统中仍然具有较高的应用价值。

在旅游领域，国内外研究通常围绕景点推荐、旅游路线规划、兴趣建模和实时导航等方向展开。部分系统通过用户历史访问记录和评分行为构建推荐模型，部分系统结合地理位置、景点标签和上下文信息实现内容推荐，还有一些系统进一步融入社交行为、评论情感分析或知识图谱，以提升推荐准确率和语义表达能力。总体来看，旅游推荐系统正由单一的景点排序，逐步发展为兼顾个性化、场景化和解释性的综合服务系统。

但在实际教学和毕业设计场景中，过于复杂的算法往往会带来实现难度高、数据依赖强、演示不稳定等问题。因此，许多可落地的毕业设计更适合采用结构清晰、逻辑完整且便于复现的推荐方案。本文系统采用基于用户协同过滤的方案，并结合浏览、收藏、评分等行为构建用户画像，在保证实现难度可控的前提下，使系统具备一定的推荐质量和展示效果。

### 1.3 课题研究内容与主要工作

围绕岳麓山景点推荐场景，本文主要完成了以下工作：

（1）设计并实现了用户认证与权限控制模块。系统支持用户注册、登录、退出登录等功能，并通过 JWT 机制完成统一身份校验，保证不同用户角色的访问安全。

（2）设计并实现了景点信息展示与交互模块。用户可以查看景点详情、浏览景点信息、收藏感兴趣的景点、提交评分和评论，并查看自己发布过的评论内容。

（3）设计并实现了基于用户协同过滤的推荐模块。系统综合用户浏览、收藏和评分等行为，计算用户兴趣偏好并生成个性化推荐结果；对无历史行为的新用户，则采用热度推荐进行冷启动处理。

（4）设计并实现了推荐理由与用户兴趣画像展示。系统不仅给出推荐结果，还会说明推荐原因，并在首页展示用户行为统计、偏好标签和兴趣摘要，以增强推荐结果的解释性。

（5）设计并实现了经典路线匹配模块。系统根据用户偏好的景点集合，对管理员预设的游玩线路进行匹配排序，帮助用户形成更适合自身兴趣的游览方案。

（6）设计并实现了后台管理与数据看板模块。管理员可以对景点、路线、评论和用户信息进行管理，同时通过统计图表查看系统运营情况，便于演示和分析。

（7）设计并实现了 AI 导游模块。系统接入大模型问答能力，为用户提供景区相关的辅助问答服务，进一步丰富系统功能。

### 1.4 论文组织结构

## 第2章 需求分析

### 2.1 系统目标

岳麓山景点推荐系统的建设目标，是围绕游客在景区浏览前、浏览中和浏览后的信息需求，提供一套兼具推荐能力、交互能力和管理能力的 Web 平台。系统需要在满足基础景点信息展示的同时，进一步结合用户行为数据，为游客提供个性化推荐结果与路线参考，以降低游客的选择成本，提高游览效率。

从功能目标来看，系统希望实现三个层次的能力。第一层是基础信息服务，即能够展示景点名称、简介、标签、票价、建议游玩时长等内容；第二层是交互服务，即支持收藏、评分、评论和浏览记录等行为；第三层是智能服务，即通过协同过滤推荐、路线匹配、推荐理由和数据看板等内容，为系统增加一定的智能化与可解释性。

### 2.2 用户角色分析

系统主要包含两类用户角色：普通游客和管理员。

普通游客是系统的主要使用对象。未登录用户可以浏览首页推荐、查看景点列表、进入景点详情和查看线路信息；登录后，用户可以执行收藏、评分、评论、查看个性化推荐和查看个人评论等操作。普通游客的核心需求在于快速获取与自身兴趣匹配的景点信息，并尽可能减少筛选成本。

管理员负责系统内容与数据维护。管理员可以对景点、路线、评论和用户进行管理，并查看系统统计数据。管理员的核心需求在于保证景区数据完整、内容合法、运行状态可控，同时通过后台看板掌握系统整体使用情况。

### 2.3 功能需求分析

#### 2.3.1 认证与用户管理

系统应支持用户注册和登录功能，注册时需要填写用户名、密码和昵称。登录后系统通过 Token 维持登录状态，用户在不同页面之间切换时无需重复登录。对于管理员用户，系统应提供对应的后台入口，并保证普通用户无法直接访问后台管理页面。

#### 2.3.2 景点浏览与详情展示

系统应提供景点列表页和景点详情页。列表页用于展示景点概览，支持搜索、筛选和分页；详情页用于展示景点的详细介绍、标签、价格、游玩时长、图片和评论信息。用户在进入详情页时，系统应自动记录一次浏览行为，为后续推荐算法提供数据支持。

#### 2.3.3 收藏、评分与评论

用户登录后应能够收藏或取消收藏景点，并对景点进行评分和文字评论。评分用于反映用户对景点的满意程度，评论用于补充更具体的评价信息。系统应支持用户查看自己发布过的评论，以便形成完整的个人行为记录。

#### 2.3.4 个性化推荐与冷启动

系统应能根据用户历史行为生成个性化推荐结果。对于有足够行为数据的用户，系统采用协同过滤方式生成推荐列表；对于行为数据不足的新用户，则采用热度推荐作为冷启动策略，避免首页出现空结果。

#### 2.3.5 路线推荐与后台管理

系统应支持线路列表展示，并根据用户偏好对线路进行匹配排序。后台管理模块应支持景点、路线、评论和用户的维护功能，并提供数据看板用于展示系统统计信息。

### 2.4 非功能需求分析

#### 2.4.1 可用性需求

系统应保证前后端页面结构清晰、功能入口明确、用户操作流程简单，便于普通用户快速上手。界面设计应保持统一风格，减少理解成本。

#### 2.4.2 稳定性需求

系统应在正常访问条件下稳定运行，推荐结果、评论数据和后台管理功能应保持一致性，避免出现数据不同步或页面展示错误的情况。

#### 2.4.3 可维护性需求

系统应采用前后端分离和分层设计方式，便于后续在不破坏原有结构的基础上进行功能扩展，例如新增统计模块、扩展推荐策略或接入新的 AI 服务。

#### 2.4.4 可展示性需求

作为毕业设计系统，除功能正确外，还需要具备较好的演示效果。因此系统在设计时加入了兴趣画像、推荐理由、排行榜和后台图表等可视化内容，使系统不仅“能用”，而且“好讲、好演示”。

### 2.5 本章小结

本章从系统建设目标、用户角色、功能需求和非功能需求四个方面对岳麓山景点推荐系统进行了分析。通过需求分析可以看出，系统不仅要满足景点浏览和基础信息展示的需要，还要在推荐、交互、管理和可视化等方面形成较完整的功能闭环。基于这些需求，下一章将进一步对系统的总体架构、技术选型和数据库设计进行说明。
